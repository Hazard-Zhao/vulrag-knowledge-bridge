## 分工与目录

- baseline-primevul：本侧维护样本清单、模型配置、模型调用及 predictions.jsonl。名称只是建议，不表示已接入 PrimeVul 数据。
- guard-validation：同伴维护执行环境、验证脚本、原始日志及 evidence.jsonl，消费本侧已有预测，不重复调用检测模型。
- shared/：双方合并同一版本的 samples.jsonl、字段约定和知识索引后再开始实验。
- results/<run_id>/：分别存放 predictions.jsonl、evidence.jsonl、requests.jsonl 和关联日志；各分支通过合并提交或 PR 共享已提交结果。

GitHub 仓库用于版本化文件。README 说明检索与导出在本机执行；当前链接没有证明存在可远程执行的云环境。

## 三种标识分别管理

1. knowledge_id：固定文件版本、文件哈希和从 0 开始的数组下标共同定位，例如 vulrag-original-cwe787@4802921:0。索引必须随固定文件共享；更新文件时创建新版本，不沿用旧索引。
2. pair_id：保留本地既有 CWE:CVE:原始记录ID 格式；多函数、多个修复或多个来源记录必须使用不同原始记录ID。新数据使用带数据集名称和版本的 ID，CVE 只是关联字段。
3. sample_id：pair_id + ':' + variant，variant 为 vulnerable 或 patched。其他变体必须另行命名并登记父样本。代码哈希变化就创建新样本版本，不覆盖旧记录。

samples.jsonl 每行至少包含 schema_version、sample_id、pair_id、dataset、dataset_revision、cve_id、cwe、variant、code_path、code_sha256、source_commit、split。code_sha256 按共享代码文件的原始字节计算；双方验证相同哈希后执行。

## 结果字段

predictions.jsonl 每行至少包含：

- schema_version、run_id、sample_id、code_sha256、method、model、prompt_sha256、config_sha256。
- prediction：vulnerable / safe / unknown；status：completed / error / pending。
- knowledge_ids、knowledge_file_sha256、response_path、created_at。

只有 status=completed 且解析有效才计为完成。错误和无法解析不能算 safe。真实标签单独保存在评估清单中，不放入模型提示。

evidence.jsonl 每行至少包含：

- schema_version、run_id、sample_id、code_sha256、evidence_id。
- validation_method、command、environment_digest、source_commit、tool_versions。
- status：triggered / not_triggered / inconclusive / build_failed / timeout；exit_code、log_path、log_sha256、created_at。

not_triggered 只表示当前测试未触发，不能直接等同于安全。一次样本可有多条 evidence_id，不应压成单个布尔值。

按 (run_id, sample_id, code_sha256) 对齐预测和证据；同一次运行的多种模型方法以 method 区分，多次执行以 evidence_id 区分。缺项、哈希不同、重复预测分别报告，禁止静默丢弃或覆盖。

## 模型调用统一入口

仅本侧发起检测模型请求。同伴需要新增方法或样本时，先提交请求清单，由本侧统一调度。run_id 绑定不可变配置，方法、模型、提示、检索参数或数据变化时使用新 run_id。

去重键至少包含 run_id、sample_id、code_sha256、method、model、prompt_sha256、config_sha256；多阶段 RAG 还应包含 stage、knowledge_id 和实际请求体哈希。复用已成功请求，保存每次尝试。请求发出后中断且无法确认服务端状态时标记 unknown，先核查再重试。

使用单一调用进程和持久化请求台账；分支各自的本地锁不能提供跨机器互斥。密钥通过环境变量或本地隐藏输入提供，不提交仓库。

## 实验边界

该 JSON 是用途、功能、漏洞行为与修复行为的文本知识，不含代码字段，也不是 PrimeVul 样本清单或执行证据库。仓库 README 说明代码检索另取上游带源码 JSON。

现有仓库检索为代码单路 BM25，每 CVE 最多一条、前三个正分候选；本地 v2 是三路检索融合 Top-10。两者必须用不同 method/config 标识，不把结果合称同一复现。

评估时排除整个评估批次的同 CVE 知识并检查代码重复与近重复。仓库 README 将 oracle 库限定为单独诊断；不得混入正式泛化评估。由漏洞版选取共享知识的实验也应标记为配对诊断。
